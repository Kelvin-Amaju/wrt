# OrbitQA v0.8 Per-Link Device Matrix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v0.7 shared-run model with a per-link/per-device matrix where every generated instance owns an independent browser/device lifecycle, timer, proxy reservation, diagnostics, interaction flow, visible operator pointer/touch marker, and cleanup.

**Architecture:** The renderer builds `QaTargetPlan[]`, validates it with `src/shared/qaMatrix.ts`, and sends `QaRunRequestV2` over the existing QA IPC. `electron/work-unit-scheduler.cjs` expands plans into immutable work units and drives a concurrency-limited queue; `electron/qa-runner.cjs` launches each work unit according to its device kind and owns per-work-unit proxy/timer/cleanup. Smart Interaction is rebuilt around `scroll-surface-driver.cjs`, `blocking-surface-resolver.cjs`, and the visual-only `interaction-indicator.cjs`.

**Tech Stack:** TypeScript 5.9, React 19, Electron 38, Playwright 1.63, Vitest 3, Node `node:test`.

**Spec:** `docs/superpowers/specs/2026-09-15-v0.8-per-link-device-matrix-design.md`

## Global Constraints

- OrbitQA remains an authorized QA/testing tool; no fingerprint spoofing, anti-detection bypass, or CAPTCHA/human-verification solving.
- Ads remain enabled; blocker handling dismisses only safe page-blocking surfaces.
- Maximum 20 target plans, 12 launch groups per target, 50 generated work units, and global active concurrency 1-5.
- Every pool-backed work unit gets its own reservation key, browser/device route verification, independent timer, and cleanup.
- Timers never reset because of navigation, redirects, popups, manual tabs, or interaction steps.
- Visible interaction indicators are visual-only, use `pointer-events:none`, and never become the source of truth for clicks/taps.
- Existing `qa:startRun`, `qa:stopRun`, and QA event IPC remain the external transport.
- Renderer state never receives proxy passwords or provider access keys.
- No unsupported configuration silently downgrades to direct networking, desktop, another device, or another browser.
