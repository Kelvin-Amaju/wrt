# OrbitQA v0.9 Device Realism & Consistency Design

## Goal

Make OrbitQA's desktop, Android mobile emulation, Android AVD, Local iOS Compatibility, and Real iOS sessions internally consistent, observable, and closer to normal manual QA behavior without adding stealth, anti-detection, CAPTCHA bypass, fingerprint forgery, or unsupported hardware spoofing.

## Product decisions

- OrbitQA reports browser/device identity truthfully. It never patches `navigator.webdriver`, fabricates canvas/WebGL/audio fingerprints, overrides hardware APIs, or hides automation from sites.
- Desktop uses the browser engine's native identity and is checked for internally contradictory mobile signals.
- Android mobile emulation uses Playwright-maintained device descriptors when available; OrbitQA falls back only to its vetted profile when a descriptor is unavailable.
- Android AVD is treated as a real Android runtime. Critical contradictions such as a non-Android user agent or no touch support fail the work unit.
- Local iOS Compatibility remains explicitly a compatibility mode. iOS-like viewport, DPR, touch, locale, timezone, and browser identity are checked; host/platform limitations are warnings rather than false claims.
- Real iOS provider diagnostics remain provider-observed and are not rewritten.
- Manual-QA realism uses bounded timing variation for observation, typing, scrolling, and post-action pauses. This is for realistic QA pacing, not bot-evasion.

## Architecture

### 1. Device consistency module

Create `electron/device-consistency.cjs` as a pure module with three responsibilities:

1. Normalize a device expectation from execution kind, selected profile, browser, context options, locale, and timezone.
2. Collect runtime identity from the page: user agent, platform, touch points, viewport, screen, DPR, locale, timezone, `navigator.webdriver`, hardware concurrency, and device memory when available.
3. Build a consistency report with per-check status (`pass`, `warning`, `fail`, `not-applicable`), severity, expected value, observed value, and operator detail.

Critical failures:

- Android emulation/AVD: missing Android UA token, no touch support, or gross viewport/DPR contradiction.
- Local iOS Compatibility: missing iPhone/iPad-style browser UA or no touch support. Platform/host limitations are warnings.
- Desktop: a mobile-only UA paired with desktop mode is a warning, not an automatic failure, because browser-native identity may be intentionally configured outside OrbitQA.

`navigator.webdriver` is diagnostic-only. OrbitQA reports the value and does not alter it.

### 2. Runner integration

`electron/qa-runner.cjs` will:

- resolve Android emulation profiles with Playwright descriptors first;
- emit a new `identity-diagnostics` event after privacy diagnostics and before behavior steps;
- stop a work unit on critical Android identity failures;
- keep Local iOS compatibility limitations visible as warnings instead of pretending they are real iPhone hardware;
- preserve existing proxy, privacy, timer, STOP, screenshot, and queue behavior.

### 3. Manual-QA pacing

Create `electron/qa-pacing.cjs` with deterministic per-work-unit pacing derived from a seed. It returns bounded values so tests are repeatable while simultaneous WorkUnits do not all move with identical cadence.

Default ranges:

- initial observation: 900-1800 ms;
- between scroll phases: 450-1100 ms;
- typing delay: 45-95 ms per character;
- short thinking pause before a safe action: 180-520 ms;
- post-action observation: 500-1200 ms;
- scroll chunk size: 42-78 px;
- scroll delay: 45-95 ms.

No arbitrary external navigation, no random ad clicks, no human-verification interaction, and no unsafe form submission are added.

### 4. Renderer

Add a Latest Device Consistency panel to Test Runs. It shows:

- overall status;
- selected mode/profile;
- each consistency check and observed value;
- a clear note when Local iOS is compatibility-only;
- a clear automation-observability row for `navigator.webdriver` without attempting to hide it.

Only the latest report is shown in the side panel; the Activity Log remains per-WorkUnit and identifies which WorkUnit produced the event.

## Data contracts

Backend identity report:

```js
{
  overall: 'pass' | 'warning' | 'fail',
  blocked: boolean,
  blockingReasons: string[],
  mode: string,
  profile: string,
  checks: [
    {
      key: string,
      label: string,
      status: 'pass' | 'warning' | 'fail' | 'not-applicable',
      required: boolean,
      expected: string,
      observed: string,
      detail: string,
    }
  ],
  observed: {
    userAgent: string,
    platform: string,
    maxTouchPoints: number,
    viewport: { width: number, height: number },
    screen: { width: number, height: number },
    devicePixelRatio: number,
    locale: string,
    timezoneId: string,
    webdriver: boolean,
    hardwareConcurrency: number | null,
    deviceMemory: number | null,
  }
}
```

Renderer event:

```ts
{
  type: 'identity-diagnostics',
  identityDiagnostics: DeviceIdentityReport,
  workId: string,
  ...existing per-work-unit metadata
}
```

## Testing

- Pure unit tests for expectation building and report severity.
- Regression test that Android critical mismatch blocks behavior.
- Regression test that Local iOS platform mismatch remains a warning.
- Regression test that `navigator.webdriver` is reported but never rewritten.
- Unit tests for deterministic bounded pacing.
- Smart Interaction tests proving supplied pacing controls typing/scroll/observe delays without relaxing safety exclusions.
- Renderer test proving the device consistency panel renders the latest report.
- Full Electron Node suite, renderer/Vitest suite on the user's Windows installation, TypeScript/Vite build, and browser-health suite before release acceptance.

## Non-goals

- CAPTCHA automation or challenge solving.
- Anti-detection patches.
- Canvas/WebGL/audio fingerprint randomization.
- `navigator.webdriver` hiding.
- Fake sensor, battery, GPU, codec, camera, microphone, or hardware API values.
- Random clicks on ads or promotional overlays.
